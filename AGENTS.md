# AGENTS.md — local-transcribe

Spec source of truth: `/home/gsierock/obsidian_vaults/gs_n/local-transcribe/MVP.md`. The app is **Tauri-only** — there is no PWA and no in-browser ASR engine. Scaffolded: Vite React-TS + Tauri v2 (see README.md).

## Response style
- **Be concise. Every response.** Short sentences, bullet points, no filler, no restating the request, no play-by-play of tool calls. State what changed and the command/result that verified it. Skip optional commentary unless asked.

## Design
- **Every UI change starts from `DESIGN.md`** (Dell 1996 catalog language: black page frame, ribbon cards, tint family, Arial Black / Helvetica / Times, 0 radius, no soft shadows). Check its rules before touching CSS or markup; `docs/REDESIGN.md` maps it onto the app's screens and components.

## Intended stack
- TypeScript + React + Vite, packaged with Tauri v2 (`src-tauri/`). Test: Vitest + Playwright.
- Audio: `MediaRecorder` primary (§8); Web Audio API / AudioWorklet allowed per recommended stack (§6) for decode/resample only.
- Storage: OPFS for audio chunks/blobs, IndexedDB for meetings/segments/settings/model metadata. Never store large audio in IndexedDB. OPFS/IndexedDB are the source of truth; the desktop shell also mirrors finished meetings to a local folder.
- Transcription: **the native desktop CLI is the only ASR path** (whisper.cpp / voxtype) behind the `ASREngine` interface. Decode/resample to chunks before ASR (§12). No network calls for audio/transcripts.
- **Quality lever = model size, not engine.** `nativeAccuracyHint()` (model-manager) nudges toward `large-v3-turbo` (Whisper) or `parakeet-tdt-0.6b-v3`; `describeNativeRuntime()` shows the desktop backend + acceleration in the UI. Native model names are the CLI's (`large-v3-turbo` default/recommended, Parakeet best) and native language options include an honest `auto` (whisper.cpp can detect).
- **ASR is not covered by Playwright here:** no display/GPU/native CLI in CI. Playwright only tests the deterministic UI (loader/error/settings states); validate DSP/decoding changes with the dev bench (`bench/`) or a Node probe.

## Desktop (Tauri) native path
- Tauri v2 shell in `src-tauri/`. It shells out to a CLI. **Zero-setup installs:** release builds bundle whisper.cpp (`whisper-cli`, pinned by `WHISPER_CPP_VERSION` in `release.yml`) as the sidecar `lt-whisper`, built per target by `scripts/build-engine.sh` (portable: `GGML_NATIVE=OFF`, AVX2 baseline on x86, no OpenMP, static CRT/libstdc++, Metal on macOS, clang-cl for Windows ARM64; smoke-tests the JFK sample when the runner can execute it) and wired in via `--config src-tauri/tauri.engine.conf.json` (externalBin + its MIT licence). Local `npm run tauri:build` without that config stays engine-less. `cmake` is absent in this sandbox (a PyPI `cmake` in a scratch venv works for testing the script).
- Rust commands (structs camelCase): `native_asr_status`, `native_asr_models`, `native_asr_download_model`, `native_asr_enable_gpu`, `native_asr_transcribe`, `native_asr_cancel`; live: `native_live_transcribe`, `native_live_cancel`. Backend discovery: `$WHISPER_CLI_PATH` → `whisper-cli|whisper-cpp|main` → `voxtype` (PATH **plus** `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin` — Finder/launcher apps get a minimal PATH) → the bundled `lt-whisper` next to the app executable (`NativeAsrStatus.bundled`). Downloads go to the app's own model dir (`app_model_dir`: `~/.local/share/local-transcribe/models`, `~/Library/Application Support/Local Transcribe/models`, `%LOCALAPPDATA%\Local Transcribe\models`); `native_asr_download_progress` reports bytes for the progress bar and a download whose size ≠ the HTTP Content-Length is rejected. `NativeAsrStatus.recommendedModel` is the first-run model (`large-v3-turbo-q5_0`, ~550 MB, for whisper.cpp; `large-v3-turbo` for voxtype).
- **GPU acceleration is root-only:** `native_asr_enable_gpu` runs `voxtype setup gpu --enable` via `pkexec` then `sudo -n` (returns the manual `sudo …` hint on failure). `NativeAsrStatus.gpu` (`GpuInfo`: `available/active/backend/devices/hint`) comes from `voxtype setup gpu --status`; Settings shows it and offers an Enable button only when `gpu.available && !gpu.active`. Enabling GPU switches the voxtype variant (e.g. Vulkan Whisper); Parakeet additionally needs the ONNX+CUDA/MIGraphX variant (`sudo voxtype setup onnx --enable`).
- **Desktop capture needs the Rust permission handler:** `src-tauri/src/lib.rs` registers `.on_permission_request` allowing `Microphone`/`Camera`/`DisplayCapture`. On Linux WebKitGTK denies any media request the embedder does not handle, and `PermissionResponse::Default` resolves to Deny — that is why `getUserMedia`/`getDisplayMedia` fail with a cryptic `NotAllowedError` in the desktop shell. Tauri 2.12 exposes the handler at app, `WebviewBuilder` and `WebviewWindowBuilder` level (the webview-level handler wins; app-level is the fallback). No extra cargo dependency is needed.
- **Settings live in a file, not the webview profile:** `src-tauri/src/settings.rs` (`native_settings_load` / `native_settings_set`, `<app_config_dir>/settings.json`, 0600, atomic write + `.bak`). `db.kvGet/kvSet/kvDelete` route every key except `calendar-cache:*` there on desktop (`src/platform/native-settings.ts`; migrates the IndexedDB value on first read, `null` = tombstone), and `src/platform/prefs.ts` (`getPref`/`setPref`) does the same for the former localStorage prefs; `main.tsx` loads the file before first render. Reason: the AppImage bundles Ubuntu 22.04's WebKitGTK (2.50); an IndexedDB written by a newer host WebKit (2.52 writes `MetadataVersion 2`; e.g. a local build or .deb/.rpm sharing `~/.local/share/io.localtranscribe.app`) fails in the AppImage with "Unable to establish IDB database file", which used to wipe all config and block model downloads. Outside the desktop shell (or when the mock returns `null`) kv falls back to IndexedDB.
- **Unreadable IndexedDB:** `openDatabase` never caches a failed open (one retry after 400 ms), reopens after `versionchange`/`close`, and throws `DatabaseOpenError`; the store sets `databaseError` and the Dashboard shows a banner whose **Start with a fresh database** calls `native_reset_webview_database(origin)` (Linux: moves `databases/indexeddb/v1/<origin>` to `<data>/idb-backup-<ts>/`, never deletes) and relaunches. Covered by `e2e/settings-persistence.spec.ts`.
- **Relaunch (update / reset) goes through `relaunch::relaunch`:** it spawns the AppImage (or exe) with `LT_RELAUNCH_WAIT_PID`, and the new instance waits for the old process and its WebKit children before opening the profile; the old one exits gracefully so WebKit flushes storage.
- **AppImage media stack (WebKitGTK 2.50 + GStreamer 1.20 from Ubuntu 22.04):** WebKit captures, records, plays and decodes through GStreamer, and AppRun points GStreamer at the bundle only. Release builds therefore pass `--config src-tauri/tauri.appimage.conf.json` (`bundleMediaFramework`) with `GSTREAMER_PLUGINS_DIR` from `scripts/gst-plugins.sh` (curated list — never souphttpsrc, whose libsoup2 aborts WebKit's libsoup3 process). Without plugins getUserMedia fails with `OverconstrainedError` "Invalid constraint" ("0 devices"). WebKit refuses WebM/Ogg MediaRecorder on GStreamer < 1.24.9 and enables MP4 only when an AAC encoder exists (`voaacenc`), so the AppImage records `audio/mp4;codecs=opus` (`CANDIDATE_MIME_TYPES` order; AAC recordings fail to decode via faad). **Never use `<audio>`/`<video>`/`new Audio()`:** each is a GStreamer playbin whose teardown deadlocks the web process (`gst_pad_stop_task` under wavparse/decodebin on the main thread) until WebKit's watchdog kills it (SIGTRAP on `WatchDogQueue`) — the "app crashes after Stop" bug. Meeting Detail plays through `src/audio/player.ts` (`PcmPlayer`: decodeAudioData → mono 24 kHz Int16, 2 s AudioBufferSourceNode slices on one shared, never-closed `playbackContext()`; output routing via `AudioContext.setSinkId`) and `AudioPlayer.tsx` (play/pause, ±15 s, seek slider, waveform; transcript timestamps seek); import measures duration with `OfflineAudioContext`. `lib.rs` gives the bundle its own `GST_REGISTRY_1_0`. `proc::bundle_root()` also detects AppImages run without `$APPIMAGE`. Validate media changes on the real AppImage (e.g. WebKitWebDriver from Ubuntu's `webkit2gtk-driver` 2.50.4 + `TAURI_WEBVIEW_AUTOMATION=true`), not only Playwright.
- **Spawn external programs only via `crate::proc::command()`** (`src-tauri/src/proc.rs`), never `Command::new`: inside the AppImage, AppRun points `LD_LIBRARY_PATH` / GTK / GIO / GStreamer / `XDG_DATA_DIRS` / `PATH` into `$APPDIR` (Ubuntu 22.04 libs), and a host `curl` inheriting that dies with `symbol lookup error … nghttp2_option_set_no_rfc9113…`. `command()` strips `$APPDIR` entries for children (no-op outside an AppImage).
- Frontend bridge is `src/platform/desktop.ts` (`invokeDesktop` reads `window.__TAURI_INTERNALS__`) — **no `@tauri-apps/api` dependency**. `isDesktopApp()` gates storage-mirroring and backend probes.
- **Local files (desktop):** finished meetings are mirrored to `<Documents>/Local Transcribe/<title-id>/` (audio tracks + `transcript.txt|md|json` + `meeting.json`) by the pure-Rust commands `native_storage_dir` / `native_save_file` / `native_open_storage_dir` (`src-tauri/src/storage.rs`; `safe_relative` rejects absolute/`..` paths). External links go through `native_open_url` (http(s)-only) + `openExternalUrl()` — the webview swallows `target="_blank"`. Frontend: `src/platform/desktop-storage.ts` + `src/features/meetings/disk-sync.ts` (`mirrorMeetingToDisk`), called best-effort from `store.tsx` after stop and after transcription. **Audio is mirrored live:** while recording, `LiveAudioMirror` (fed by `recorder.onChunk`, in order) appends each chunk to `audio.<ext>` via `native_save_file { append: true }` (MP4 repaired on the fly by `Mp4StreamRepair`), so Stop writes only the small files (`mirrorMeetingToDisk(meeting, 'skip')`); if a live write failed, Stop copies from storage in 2 MB slices (`saveBlobToDisk`). Later mirrors (transcript/agenda) default to `'if-missing'` (`native_storage_file_size`) and never re-copy audio. Covered by `src/features/meetings/disk-sync.test.ts` + `e2e/live-disk-mirror.spec.ts`. Controlled by the `desktop-save-to-disk` localStorage pref and the Settings **Local files** card. OPFS/IndexedDB remain the source of truth.
- `NativeASREngine` (`src/asr/native-engine.ts`) runs `preprocessForASR`, then ships 16 kHz mono WAV as base64. Chunking depends on the backend (`chunkModeForBackend`): **whisper-cli** (timestamped JSON) gets 10-minute `windows`; **voxtype** (plain text only) gets `speech` chunks from `planSpeechChunks` (`src/asr/chunking.ts`: ≤24 s of speech, cut at pauses, long silences removed via `assembleChunk`, one segment per chunk spanning its real start/end). Do not raise the 24 s budget: audio up to Whisper's 30 s window edge loses trailing words (measured). Stationary noise/silence sends nothing (no hallucinations). `NativeASREngine.initialize` throws `installHint` when no CLI is found. `TranscriptionService` creates one engine per run and **serializes runs** (the Rust side has one child-process slot); queued runs show stage `queued`.
- **One-click first run:** Dashboard "Set up transcription" and Meeting Detail "Download model & transcribe" (`setupAndTranscribe`) download the recommended model with live progress (`ModelDownloadProgress`) and transcribe — never send users to Settings to get started. Covered by `e2e/first-run.spec.ts`.
- **macOS:** `src-tauri/Info.plist` (merged by Tauri) carries `NSMicrophoneUsageDescription` — without it macOS silently denies the microphone. `src-tauri/Entitlements.plist` (audio-input, network client) applies once the app is Developer-ID signed.
- Model + language storage are native-only: `getModelMeta()` / `setModelMeta()` (key `asr-model-meta-desktop`) and `getTranscriptionLanguage()` / `setTranscriptionLanguage()` (key `asr-language-desktop`).
- Native ASR is not exercised by Playwright (no display/GPU in CI); unit-test the pure helpers and keep the browser suite green.
- **Cross-platform (Linux/Windows/macOS):** the frontend is platform-agnostic.
  Rust uses only std + the 5 crates in `Cargo.toml` (no `dirs`/`reqwest`; `tauri-plugin-updater` is the one plugin, for in-app updates).
  OS-specific code paths: `models.rs` (`home_dir` falls back to `USERPROFILE`,
  `split_paths` for `PATH`, `.exe` probing in `which`, per-OS model dirs) and
  `native_asr.rs` (generic `ggml-*.bin` download from Hugging Face via curl with
  a Windows PowerShell fallback; `valid_model_name` guards the URL/path).
  The Settings GPU card renders only for the voxtype backend (`nativeStatus.backend`).

## Core rules (from MVP — do not violate)
- Recording and transcription are separate. Recording must fully work with no ASR model installed. `transcriptionStatus: "not_started"` is valid. Never auto-transcribe after stop. Transcript is derived data; recording is authoritative (§11).
- **Live transcription (user-requested exception to §5/§20 "no live transcription"; desktop, opt-in, off by default):** Settings → Models **Live transcription** card (pref `live-transcription`, model pref `live-transcription-model` = an installed native model, default/recommended `base`; **Download base** fetches it via `native_asr_download_model` without changing the main model; New Meeting mirrors the switch). `src/audio/live-tap.ts` (`LivePcmTap`: ScriptProcessorNode on the recorded stream — the mix for Mic + Device, reusing the mixer's AudioContext; detached before the sources stop; dropped while paused) → `Downsampler` → `LiveSegmenter` (`src/asr/live-segmenter.ts`: re-runs `planSpeechChunks` on the pending audio, emits a chunk once 1 s follows it, ≤10 s per utterance) → `LiveTranscriber` (`src/asr/live.ts`: one utterance at a time, gives up after 3 errors, never throws into the recorder) → Rust `native_live_transcribe` (`src-tauri/src/live_asr.rs`: the regular whisper.cpp/voxtype `transcribe_blocking` on its own child slot `LiveState`, so `native_asr_cancel` never kills it). **Engines must stay fully local with no telemetry** — Cactus Whistle was evaluated and rejected because its engine binary ships with telemetry on by default. On Stop the queue drains (Meeting Detail shows the normal loader; Cancel/delete stop it) and the live text is committed as the transcript with `Meeting.transcriptSource {kind:'live', model}`; whole-file runs set `kind:'file'`. Re-transcribe always re-runs the whole recording. A failed or cancelled live run leaves the meeting `not_started`. Covered by `src/asr/live*.test.ts`, `cargo test live_asr` and `e2e/live-transcription.spec.ts`.
- Transcription failure must never destroy/invalidate the recording. Failure UI: "Your original recording is still safe." + Retry (§13).
- Speaker (`getUserMedia({audio:true})`), Device (`getDisplayMedia({video:true,audio:true})`), and **Two-way** (`dual`: both at once) modes. Single-source modes never mix streams. Label as "Device Audio", never promise system-audio capture (§2). Device mode: if no audio track, show full MVP §18 message — do not request mic permission for device mode; request mic only for mic/dual starts. `dual` is an intentional extension beyond MVP §2 (user-requested, for Zoom calls): mic + device are **mixed into one track** by `MixedAudioSource` (`src/audio/mixed-audio.ts`: Web Audio → limiter → mono `MediaStreamAudioDestinationNode`; any input ending ends the mixed track so the recorder reports it), recorded flat like single-source modes — one file, no Me/Others split (user-requested). Legacy two-track recordings (`meetings/{id}/{microphone|device}/`, `DUAL_TRACKS`, `trackSpeakerLabel`) stay readable/transcribable. New Meeting warns (`.warn`) to wear headphones: AEC is off and could not cancel another app's playback anyway, so speakers put a delayed echo of the call in the mix.
- **Linux system audio (user-requested exception to §2/§5 "OS audio hacks"):** WebKitGTK's getDisplayMedia is video-only and WebKit never lists monitor sources, so on Linux the desktop shell exposes the default output's monitor as a virtual input while recording: `src-tauri/src/system_audio.rs` (`native_system_audio_status|start|stop`, `pactl load-module module-remap-source … source_name=local_transcribe_system_audio`, label `Local_Transcribe_system_audio` — no spaces, PipeWire's pulse server truncates quoted values). The source is removed on stop, on app exit (`RunEvent::Exit`) and at startup (crash leftovers). Frontend `src/audio/system-audio.ts` (`SystemAudioSource`: finds the device via enumerateDevices, getUserMedia with echoCancellation/noiseSuppression/AGC off); the store uses it for the `device` track of Device Audio and Two-way when `systemAudio.available` (no screen picker; this path does use getUserMedia). Covered by `src/audio/system-audio.test.ts` and `e2e/system-audio.spec.ts`. It records the output chosen in **Record sound from** (`native_system_audio_outputs` parses `pactl list sinks`; `native_system_audio_start({ sink })` validates the name (`valid_sink_name`) and falls back to the default sink when it is gone), else the output that was default when recording started.
- **Audio I/O selection:** `src/audio/devices.ts` (prefs `audio-input-device` / `audio-playback-output` = `{deviceId,label}` JSON, `audio-system-output` = sink name; '' = system default) + `src/app/components/AudioDevices.tsx` (`AudioDevicePickers`), shown in Settings → App **Audio devices**, on New Meeting (mic for Speaker/Mic + Device; output on Linux for Device/Mic + Device) and Meeting Detail (playback output, only where `setSinkId` exists — not WebKit). Saved devices resolve by id, then label (ids change); a missing device falls back to the default with a note. The virtual system-audio source is never listed as a mic. Covered by `src/audio/devices.test.ts` and `e2e/audio-devices.spec.ts`.
- **Recording diagnostics (every recording):** `src/audio/diagnostics.ts` (`RecordingDiagnosticsCollector`) taps each input BEFORE the Mic + Device mix (reuses the mixer's AudioContext via `MixedAudioSource.graph()`; single-source modes get their own context, closed before the sources stop) with 16k-sample analysers polled every 500 ms: level, clipping, dropouts, spectrum above 4/8 kHz (Bluetooth call mode = narrowband), mic-vs-system correlation/delay (acoustic bleed ≈ tens of ms; ~0 ms = loopback), track ended/mute and `devicechange`. Linux desktop adds the sound-server log `src-tauri/src/audio_diag.rs` (`native_audio_diag_start|peek|stop`: `pactl subscribe` + default-device/card-profile snapshots; read-only, killed on stop and app exit). Findings come from the pure `assessDiagnostics` (`src/domain/audio-diagnostics.ts`); live problems show on Active Meeting (`recordingIssues`), the report is saved as `Meeting.diagnostics` every 30 s (crash-safe) and at stop, shown as the Meeting Detail **Audio check** card and mirrored as `diagnostics.json`. Diagnostics must never affect the recording (all best-effort). Covered by `src/audio/diagnostics.test.ts` and `e2e/audio-diagnostics.spec.ts` (synthetic delayed/clipped inputs). Offline tools for exported files: `scripts/analyze-recording.py` (decode with GStreamer — ffmpeg mis-reads the app's GStreamer 1.20 MP4s, one `trun` per frame, and drops ~half the audio) and `scripts/audio-diagnose.sh`.
- **Media capture failures are turned into guidance, never raw DOMExceptions.** `src/audio/permissions.ts` (`mediaAccessError` → `MediaAccessError.failure {message, hint, retryable, code}`) classifies `NotAllowedError`/`NotFoundError`/`NotReadableError`; `microphone.ts`/`device-audio.ts` rethrow it, NewMeeting shows hint + **Try again**, and Settings has a **Grant microphone access** card (`queryMicrophonePermission()` + `primeMicrophonePermission()`, which actually triggers the permission prompt). Guidance is desktop-first (OS privacy settings, no address bar); an insecure context (`!isSecureMediaContext()`) can never prompt.
- Recording state: `IDLE → STARTING → RECORDING ↔ PAUSED → STOPPING → COMPLETED`; any active state → `ERROR` → Recover/Save/Retry (§9). Must support start/pause/resume/stop + long recordings, and survive in-app navigation (§4).
- Persist recorder chunks incrementally (`meetings/{id}/00000N.webm`; legacy two-way: `meetings/{id}/{microphone|device}/00000N.webm`) so crash recovery works. On launch, detect unfinished recording → offer Recover / Delete (§15). `recordings.ts` is track-aware: `listTracks()` + `listChunkNames(id, track)` / `readRecordingBlob(id, mime, track)`; track `''` = legacy flat single-track. Select container/codec via runtime capability check (§8). Opus at `audioBitsPerSecond: 48000` mono (≈18 MB / 50 min; 128 kbps was ≈55 MB for no ASR gain).
- Storage: check `navigator.storage?.estimate()` before recording, warn when low; storage failure during recording must surface explicitly — never report unsaved audio as saved (§19).
- Delete meeting = remove IndexedDB metadata + segments AND all OPFS chunks. No orphans (§23). Go through the store's `deleteMeeting` (cancels and awaits a running transcription first). Long-running work must never `getMeeting → saveMeeting`: use `updateMeeting` (single transaction, no-op if deleted) and `commitTranscript` (segments + status atomically, no-op if deleted) — otherwise a delete mid-run resurrects a zombie record / orphan segments.
- **Recording reliability (all engines):** OPFS files are written via `createWritable()` or, where missing (WKWebView before Safari 26), via `src/storage/opfs-writer.worker.ts` (sync access handles); `assertDurableStorage()` refuses to record without durable storage in a webview (the in-memory map is Node-only). **The AppImage's WebKitGTK 2.50 has no OPFS** (`navigator.storage.getDirectory` is missing; ≤0.1.6 silently recorded into memory): in the desktop shell `recordings.ts` then routes every call to Rust `native_recording_write|write_meta|read_meta|list|read|delete` (`src-tauri/src/recordings.rs`: `<app_data_dir>/recordings/meetings/<id>/[<track>/]<chunk>`, same layout as OPFS, atomic temp+rename writes, `valid_segment` path guard). Covered by `src/storage/recordings-native.test.ts` + `e2e/native-recording-store.spec.ts`. The recorder waits for every in-flight chunk write on stop (`drainWrites`), flushes (`requestData`) on `pagehide`/hidden, and turns an ended track / failed or self-stopped MediaRecorder into `ERROR` with `getErrorKind() === 'source'` (Active Meeting: "Recording interrupted" + Stop & keep only; Retry never resumes a dead source). Covered by `src/audio/recorder.test.ts` + `e2e/recording-reliability.spec.ts`; `.github/workflows/e2e.yml` runs the e2e suite per OS (Chromium ≈ WebView2 on Ubuntu/macOS/Windows; the `webkit` project ≈ WKWebView on macOS — recording specs only, in a persistent context via `e2e/fixtures.ts` because WebKit refuses OPFS in ephemeral contexts). Playwright's Linux WebKit has no MediaRecorder and does not launch on Arch: validate WebKitGTK recording on the real AppImage. In WebKit specs, patch page globals with `page.evaluate` after `goto`, not `addInitScript` (a persistent context's first page may miss it).
- Recording errors (§9/§19): OPFS write failures put the recorder in `ERROR` with the failed chunks held in memory; Active Meeting shows the error, hides the "being saved" note, and offers **Retry saving** (`retryPending`) or **Stop & keep what was saved**. Stopping with unsaved chunks records `Meeting.unsavedChunks` and Meeting Detail warns about the gap. Durations exclude paused time (`recorder.getElapsedMs()`); the live recording is excluded from the unfinished/recovery list, and recovered meetings get `durationMs` estimated from chunk counts (`durationEstimated`).
- The sidebar model chip (`modelChipLabel`) names the model in use; the store runs `reconcileModelMeta` whenever the native status changes, so a model installed outside the app (or a stale `not_installed`) shows as ready and a missing selection falls back to the best installed model.
- ASR model: native only. `NATIVE_DEFAULT_MODEL` / `NATIVE_RECOMMENDED_MODEL` and `NATIVE_LANGUAGE_OPTIONS` in `model-manager.ts`. Lifecycle `Not Installed → Downloading → Verifying → Installed → Loaded → Ready`; show download progress (§16). The **Settings screen (`#/settings`) owns browsing/downloading/selecting**; models are tiered S–D by `accuracy` in `src/asr/model-tiers.ts` (`nativeCatalog`/`groupByTier`), and Meeting Detail offers **only installed models**.
- Privacy: no accounts, backend, cloud, analytics/telemetry on audio/transcripts. Nothing goes online without a user action; `src/privacy.test.ts` pins every network path (webview `fetch`, Rust `curl`, deps, engine build flags) — extend it and README "Privacy: what goes online" when adding one. UI line: "Your recording and transcript stay on this device." Do not claim absolute security (§17).
  Exception: the opt-in LLM provider (`src/integrations/llm.ts`, Settings card) deliberately sends transcript text to the user's endpoint — local Ollama stays on-device, API/Open WebUI leaves the machine. The Settings card states this.
  The `opencode` preset shells headless `opencode run` via Rust (`src-tauri/src/opencode.rs`: `native_opencode_status`, `native_opencode_summarize`, registered in `lib.rs`); model is a `provider/model` id from `opencode models`, no key needed, desktop-only. The `claude` preset does the same with the Claude Code CLI (`src-tauri/src/claude_code.rs`: `native_claude_status`, `native_claude_summarize` → `claude -p --output-format json --tools "" --strict-mcp-config`, transcript on stdin, run from the home dir, session named `Meeting summary: <title>`); model = alias (`opus`/`sonnet`/`haiku`/`fable`) or full name; the returned `session_id` is kept as `Meeting.summary.sessionId` and MeetingDetail shows `cd ~ && claude --resume <id>`. `cargo test -- --ignored claude` runs the real CLI. `Meeting.summary { text (TL;DR), keyPoints, actionItems?, model, createdAt }` is written by `summarizeMeeting` in `store.tsx` and rendered by MeetingDetail. The prompt (`SUMMARY_SYSTEM` in `llm.ts`) is deliberately short: `# TL;DR` (1–2 sentences), `# Key points` (≤7 bullets), `# Action items` ("Owner: task (due)"); `parseSummaryReply` tolerates heading variants.

- **Company calendar (CalDAV / Graph / EWS):** `src/integrations/calendar.ts` (pure builders: `extractEventDraft` prefills title/day from the summary, `buildIcsEvent`/`buildGraphEvent`/`buildEwsCreateItem`, `buildTransport`/`buildTestTransport`, `validateCalendarConfig`) + `calendar-store.ts` (IndexedDB key `calendar-config`). Server address takes host/path with separate protocol (http/https) + port fields; a full URL with its own scheme is used as-is (`composeUrl`). Settings **Company calendar** card owns provider + credentials; MeetingDetail **Calendar event** card (needs a summary) prefills an editable draft (title/start/end/description/location); nothing is sent until **Approve & create on server**. Each approval creates a new event (`eventUid(meetingId, createdAt)`), appended to `Meeting.calendarEvents[]` (`CalendarEventRecord`; `Meeting.calendarEvent` = last, kept for compat). **Auto-detect** (Settings calendar card, desktop-only, `src/integrations/calendar-detect.ts` + Rust `src-tauri/src/calendar_detect.rs`): **Find in Thunderbird** — `native_calendar_thunderbird` returns only `calendar.registry.*` / `mail.server.*.{hostname,userName,type}` lines of each profile's prefs.js (profiles.ini + Snap/Flatpak/macOS/Windows roots; passwords never read), `parseThunderbird` keeps enabled `caldav` calendars; **Detect from server** — `native_calendar_probe` (one curl request, no redirects, PROPFIND/GET/POST only) walks `probeCandidates` (.well-known/caldav → SOGo → Nextcloud → Zimbra → Kerio → EWS), follows same-origin redirects only, and with a password lists calendars (principal → calendar-home-set → Depth 1). SOGo: Settings **Use SOGo address** (`sogoCalendarUrl(host, user)` → `<host>/SOGo/dav/<user>/Calendar/personal/`).
- **Calendar view (`#/calendar`):** month grid (`.cal-grid`, Monday-first) marking recorded meetings (brand dot, from the IndexedDB list) and server events (green dot). Server listing is Rust `native_calendar_fetch` (CalDAV REPORT with time-range, Graph calendarview, EWS FindItem) parsed in TS (`parseCaldavReport`/`parseGraphEvents`/`parseEwsFindItem` → `ServerEvent`). iCalendar reading lives in `src/integrations/ics.ts` (`parseIcs`): XML entities/CDATA (SOGo sends `&#13;`), TZID→local via `Intl` (unknown TZIDs = floating), all-day (`ServerEvent.allDay`), and RRULE expansion into the fetched window (DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL/COUNT/UNTIL/BYDAY/BYMONTHDAY/BYMONTH, EXDATE, RECURRENCE-ID overrides; CANCELLED skipped) — CalDAV time-range returns a recurring event's master, so without expansion recurring meetings vanish. The REPORT body is unchanged (no server-side `expand`). The header provider picker switches the active provider (`switchCalendarProvider` → `calendar-store.ts` keeps one saved config per provider + `activeProvider`, migrating the legacy single-config shape); the view refetches the visible month (and on **Refresh**). Each successful month fetch is cached in IndexedDB kv (`src/integrations/calendar-cache.ts`, key per provider+account+server+month) and shown immediately / when offline with a "saved at" note. Read-only: server events are never edited or deleted. Settings is tabbed (Models / Calendar / Team sharing / AI assistant / App); the calendar card lives under the Calendar tab.
